# MCode Space

- Repositório independente em `mcode/mcode-space`. Nunca executar Git na pasta `mcode` nem alterar o Git do portfólio.
- Ler README.md, PRODUCT.md e DESIGN.md. Aplicativo desktop Electron para Windows, com interface JavaScript nativa, xterm.js e node-pty.
- Instalar com `npm ci`; executar com `npm start`; validar com `npm test` e `npm run test:smoke`; gerar portátil com `npm run dist`.
- Manter `contextIsolation`, `sandbox` e a API explícita do preload. Não expor IPC genérico nem Node.js ao renderer. Não carregar páginas externas na janela privilegiada.
- Validar o remetente de cada IPC. Caminhos do editor/explorador passam por realpath e devem permanecer na pasta aberta; `.git` é protegido.
- Salvar arquivos exige revisão do conteúdo para detectar mudanças externas. Não remover essa proteção nem executar comandos automaticamente a partir do workspace salvo.
- Os terminais são processos reais com permissões do usuário, não uma sandbox. Encerramento e descarte de alterações exigem confirmação.
- Preservar logos originais e fontes com suas licenças. Não depender de assets fora deste repositório.
- Não versionar node_modules, dist, release, test-results, credenciais ou configurações pessoais.
- Pastas são abas independentes. Toda operação de arquivo e criação de terminal informa a raiz autorizada; nunca usar a pasta ativa global para operações iniciadas em outra aba.
- Atualização do explorador: 750ms, somente raiz e pastas expandidas, sem renderizar quando não há diferenças ou durante arraste. Não voltar com botão manual de atualizar.
- Ícones funcionais vêm do Lucide em src/icons.js. Não escrever paths SVG próprios para controles; os logos oficiais são preservados.
- Markdown usa Marked e DOMPurify. Nunca inserir HTML não sanitizado. Imagens raster locais passam pela validação de raiz/tamanho; links externos aceitam somente HTTP/HTTPS.
- Supabase: account.cjs gerencia Auth (email, Google/GitHub com PKCE), perfis e Storage. Login social usa navegador do sistema e callback com nonce no caminho em 127.0.0.1:47831. Não expor access/refresh tokens, credenciais administrativas ou cliente SDK ao renderer. A configuração embarcada contém SOMENTE URL e publishable key.
- Sessões são criptografadas no userData. Avatar é escolhido pelo diálogo nativo, validado e reencodado em PNG; bucket avatars privado com pasta auth.uid(). Perfis e fotos exigem RLS por usuário (membros de uma mesma equipe veem nome/usuário). Caixa e tarefas pertencem a uma EQUIPE (team_id) e só membros dela leem ou alteram, com RLS negando acesso anônimo e de outras equipes. Qualquer migração remota exige inspecionar o schema existente primeiro; nunca reutilizar service_role no aplicativo.
- Financeiro: interface própria em src/finance.js alterna com explorador à esquerda. electron/finance.cjs usa tabelas mcode_* e a sessão Supabase, sem Google Sheets. Toda leitura e escrita filtra pela equipe ativa (teams.current()); owner_id registra o criador e não deve filtrar leituras. Preservar proteção contra respostas de outra conta ou equipe e atualização concorrente por id/updated_at. Não enviar arquivos, pastas ou histórico de shell à nuvem.
- Personalização dos terminais usa glyph Lucide validado e color predefinida, persistidos em settings.cjs. Abas visíveis somente em layout tabs; em columns/grid, os controles ficam no cabeçalho. Borda ativa verde animada deve respeitar prefers-reduced-motion.

- Equipes (organizações): electron/teams.cjs e src/teams.js. Papéis owner/admin/member; criação, convites (código mostrado uma vez, banco guarda SHA-256), papéis e remoção só por RPCs security definer com checagem de papel. A equipe nunca fica sem dono. Equipe ativa por conta em teams.json no userData. Exclusão, saída e remoção de membros exigem confirmação nativa.
- Projeto aberto e universal: nada específico de uma empresa no código (nomes, preços, fuso horário). Contas aceitam Supabase Cloud, auto-hospedado (HTTPS) ou local (http://127.0.0.1/localhost). Logos MCode continuam sendo da marca do produto.

- Laterais: src/sidebars.js coordena Explorador, Financeiro, Tarefas, Contratos, Monitor e Auto-work, com um painel visível por vez. src/todos.js e electron/todos.cjs usam mcode_todos da equipe ativa, prazos, prioridades e atualização por id/updated_at. As laterais ativas sincronizam a cada 5 segundos.

- Agentes: electron/agents.cjs permite somente Codex, Hermes, OpenCode e Claude, resolvidos em diretórios absolutos. Nunca executar scripts de workspace como atalhos, instalar CLIs ou acrescentar flags de aprovação automática nos terminais. A restauração salva deve continuar iniciando apenas shells comuns.
- Auto-work (exceção autorizada pelo usuário): electron/autowork/ executa agentes sem confirmação interativa SOMENTE no worktree próprio da branch autowork (userData/autowork/worktrees), nunca na pasta aberta nem na main. Claude usa --permission-mode dontAsk com lista explícita de ferramentas e --setting-sources user; OpenCode usa config própria (OPENCODE_CONFIG) com bash negado exceto testes/git de leitura. Nunca usar bypassPermissions/--dangerously-skip-permissions. Commits só após testes e revisão aprovada; agentes não fazem commit/push (HEAD é verificado). Arquivos .git/.env/chaves alterados descartam o ciclo. Sem push automático. Início só por ação explícita (app ou /iniciar do chat pareado); nunca retomar ao abrir o app. Telegram: só o chat pareado por código de 6 dígitos, comandos fixos, mensagens com resumos (sem código/diff). Token do bot e chave NVIDIA criptografados com safeStorage, nunca enviados ao renderer. Cadeia: orquestrador Claude (plano do usuário, sem ANTHROPIC_API_KEY) → API NVIDIA → OpenCode grátis; implementação OpenCode+NVIDIA → OpenCode grátis → Claude.
- Monitor de tokens local: electron/agent-usage.cjs lê somente campos numéricos de logs e bancos SQLite em modo readOnly/query_only. Não retornar mensagens, credenciais, configurações ou conteúdo bruto ao renderer nem ao Supabase. Contagem agrupada por agente/pasta desde a abertura; não duplicar o mesmo consumo em múltiplos terminais. Limites só aparecem quando fornecidos pela fonte, com data do último registro. Preservar limites de leitura e indicação de contagem parcial.

- Contratos: formulário local em src/contracts.js, modelo/validação compartilhados em electron/contracts-template.mjs e PDF em electron/contracts.cjs. Validar e escapar todos os campos; exportar somente via diálogo nativo. O PDF reserva espaços para assinatura externa, sem assinar ou enviar dados. Sem dados pessoais ou preços padrão de uma empresa específica; marca do prestador é campo opcional.

- Atualizações: electron/updates.cjs usa electron-updater e releases públicas fixas caioribi7/mcode-space. autoDownload e autoInstallOnAppQuit permanecem false; baixar e instalar exigem ações explícitas. Antes de quitAndInstall confirmar descarte/encerramento e parar PTYs. Não embarcar tokens GitHub. Publicar instalador NSIS, blockmap e latest.yml juntos. Portáteis antigos migram manualmente pelo instalador.
